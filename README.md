Проверяющий загружает `.mov`, через 30–60 секунд получает вердикт «нарушение не обнаружено» или «обнаружены признаки возможных нарушений». По каждому эпизоду выдаются тип, таймкод, описание того, что видно, 1–3 кадра с размытыми лицами и ссылка на пункт норматива. Видео не покидает сервер: детектор и визуально-языковая модель работают локально, облачные AI-API не используются.

Результат — подсказка для человека. Сервис не утверждает того, чего не видно на записи: проводки, сверку и подписи он не оценивает.

## Быстрый старт

Windows, NVIDIA GPU от 8 ГБ:

```powershell
winget install astral-sh.uv Ollama.Ollama
uv sync                                  # Python 3.12, torch cu128, зависимости
ollama pull qwen3-vl:4b-instruct         # 3,3 ГБ, один раз; нужен именно *-instruct
.\serve.ps1                              # http://127.0.0.1:8000
.\tunnel.ps1                             # в другом окне: публичный HTTPS-адрес
```

При первом запуске `serve.ps1` создаёт `.env` со случайным `API_KEY`. Обработка идёт офлайн (`HF_HUB_OFFLINE=1`).

`tunnel.ps1` открывает localhost.run с keep-alive и переподключением (адрес пишется в `runs/tunnel_url.txt`), а `tunnel.ps1 -Ngrok` — ngrok со статическим доменом из `NGROK_DOMAIN`. Cloudflare quick tunnel не подойдёт, если сеть режет порт 7844.

Linux / внутренний контур банка: `docker compose up -d`. Шаги описаны в [docker-compose.yml](docker-compose.yml).

## API

Два шага, ключ — в заголовке `X-API-Key`; без него сервис отвечает `401`.

```bash
curl -X POST https://<host>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
# {"job_id":"3f2a9c1e0b7d","status":"processing"}

curl https://<host>/api/v1/jobs/3f2a9c1e0b7d -H "X-API-Key: <ключ>"
```

```json
{
  "job_id": "3f2a9c1e0b7d",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Рабочий компьютер оставлен незаблокированным при уходе кассира",
    "timecode_sec": 19.5,
    "description": "Кассир покинул рабочее место, а экран рабочего компьютера остался разблокирован…",
    "evidence_frames": [{ "timestamp_sec": 19.5, "image_base64": "/9j/4AAQ…" }],
    "rule": { "document": "Требования… № 53", "clause": "п. 53; п. 71 пп. 9)", "url": "https://adilet.zan.kz/…" }
  }]
}
```

Схема совпадает с разделом 10 ТЗ. Поля `rule`, `interval_sec`, `confidence` и `detected_by` — дополнительные, обязательные поля они не меняют. Пока видео обрабатывается, ответ — `processing` с этапом и прогрессом, при ошибке — `failed` с текстом причины.

## Как это работает

```
.mov ──► кадры 4 fps ──► RT-DETRv2: люди, ноутбук, сумки, посуда
                     ──► сцена: кассир (по треку), люди в комнате без отражений в стекле,
                          вход / выход / касса опустела, момент ухода с рабочего места
                     ──► Qwen3-VL-4B на увеличенных фрагментах, только узкие вопросы:
                          · где счётная машина, сейф, дверь — один раз на видео
                          · что в руках кассира — каждые ~1,5 с, 3 кадра подряд
                          · для пересчёта: крупный план предмета — купюры, удостоверение,
                            карта, телефон или документ; ушли ли деньги в машину
                          · при уходе кассира: экран ноутбука и что осталось на столе
                          · при входе людей: деньги на столе, кто подошёл к кассиру
                          · при приходе кассира: закрыта ли дверь
                     ──► временные правила ──► тип · таймкод · кадры · пункт норматива
```

На целом кадре 464×848 модель на 4 млрд параметров путается: может сказать «в комнате никого», когда там двое. На вырезанном фрагменте с одним вопросом она отвечает надёжно (экран ноутбука — 11 из 11 на эталонных кадрах). Поэтому детектор и наш код решают, куда и когда смотреть, а VLM — что там видно. Подробнее — в [docs/architecture.md](docs/architecture.md).

## Что ловит

| Нарушение | Что видно на записи | Норма |
|---|---|---|
| Пересчёт вручную без счётной машины | купюры в руках, кассир перелистывает их, в машину не уходят | Правила № 231, п. 9, 19 пп. 2), 41 |
| Ушёл, оставив ценности | кассир вышел, на столе деньги, сумка, планшет | № 231, п. 20, 22 |
| Деньги на столе при смене посетителя | входит следующий клиент, пачка лежит на столе | № 231, п. 20 |
| Компьютер не заблокирован | после ухода на экране рабочая программа, не экран блокировки | Требования АРРФР № 53, п. 53, 71 пп. 9) |
| Дверь кассы открыта | кассир вошла и не закрыла дверь | Правила № 14, п. 8, 16 пп. 1), 21 |
| Посторонний в зоне кассира | человек подходит к кассиру во время операции | № 14, п. 8, 21; № 231, п. 75 |
| Операция без клиента | клиент ушёл, деньги продолжают пересчитывать | № 231, п. 20, 31, 35 |
| Нет удостоверения перед операцией | у клиента начинается операция с деньгами, документ в окне −30…+3 с не показан | № 231, п. 19 пп. 1), 31 пп. 1) |
| Личные вещи, еда на рабочем месте | сумка, одежда, еда, напитки на столе | № 231, п. 12 |

Источники и то, как пункт сопоставлен с кадром, описаны в [docs/rules.md](docs/rules.md). Где норма пересказана, а не процитирована, это помечено. Где связь — толкование (телефон, еда, компьютер), в описании стоит «может указывать».

## Результаты

Прогон всех 40 уникальных видео открытого набора через HTTP API, как у жюри (`tools/eval.py --api`):

| Метрика | Значение |
|---|---|
| Точность вердикта | 65% (26/40) |
| Полнота — найдено видео с нарушением | 81% (17/21) |
| Ложные тревоги на «чистых» видео | 10 из 19 |
| Таймкод: медианная ошибка / в пределах 3 с | 4 с / 7 из 18 |
| Время обработки | 35–50 с на видео 15–25 с; до ~2 мин на видео 70–140 с |

Пороги подбирались на этом же наборе, поэтому на новых видео цифры могут быть ниже. Больше всего ошибок даёт ручной пересчёт: в «чистых» видео кассир тоже держит купюры, например разбирает их после машины. Разбор слабых мест — в [docs/limitations.md](docs/limitations.md).

Свой прогон:

```powershell
.\.venv-local\Scripts\python.exe tools\eval.py --api http://127.0.0.1:8000 --key <ключ> --tag mytest
.\tools\watch_eval.ps1 -Tag mytest      # живой дашборд в терминале
python tools\rescore.py mytest --drop unauthorized_person   # пересчёт без повторного прогона
```

## Структура

```
app/
  main.py            FastAPI: /api/v1 (ключ), /ui (интерфейс), статика
  jobs.py            очередь задач, один GPU-воркер, результаты в runs/<job_id>/
  pipeline/          video · detect · scene · vlm · analyze · rules · report · faces
  static/            веб-интерфейс
tools/               eval, rescore, watch_eval, contact_sheets, labels, probes
docs/                документация для сдачи
serve.ps1 · tunnel.ps1 · Dockerfile · docker-compose.yml
```

## Модели и лицензии

Все компоненты допускают коммерческое использование.

| Компонент | Модель | Лицензия |
|---|---|---|
| Детекция | RT-DETRv2 R50 (`PekingU/rtdetr_v2_r50vd`) | Apache-2.0 |
| Визуально-языковая модель | Qwen3-VL-4B-Instruct, Q4_K_M через Ollama | Apache-2.0 |
| Размытие лиц | YuNet (OpenCV Zoo) | MIT |
| Остальное | FastAPI, PyAV, OpenCV, transformers | MIT / BSD / Apache-2.0 |

Лица на кадрах-доказательствах размываются, распознавание личности не выполняется.
