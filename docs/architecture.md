# Архитектура

## Компоненты

| Слой | Файл | Что делает |
|---|---|---|
| API и UI | `app/main.py`, `app/static/*` | FastAPI: `/api/v1/analyze` и `/api/v1/jobs/{id}` (ключ в `X-API-Key`), те же обработчики без ключа для веб-интерфейса `/ui/*`, статика |
| Очередь | `app/jobs.py` | Задачи в памяти, один GPU-воркер. Статус `processing` с этапом и прогрессом, затем `done` или `failed`. Результат сохраняется в `runs/<job_id>/result.json` и переживает перезапуск |
| Видео | `app/pipeline/video.py` | PyAV: кадры 4 fps с точными временными метками, длинная сторона ≤ 960 px |
| Детекция | `app/pipeline/detect.py` | RT-DETRv2 (COCO): люди, ноутбук, сумки, посуда, телефон. fp16 на GPU, батчи по 8 |
| Сцена | `app/pipeline/scene.py` | Отделяет людей в кассе от людей за стеклом (по относительному размеру), сглаживает число людей, находит входы и выходы, рабочее место (ноутбук) и кассира — ближайшего к нему человека |
| VLM | `app/pipeline/vlm.py` | Клиент Ollama, ответ в JSON по схеме (structured output) |
| Логика | `app/pipeline/analyze.py` | Сканирование рук кассира, проверки в моменты событий, временные правила, удаление дублей |
| Нормы | `app/pipeline/rules.py` | Тип → документ, пункт, цитата или пересказ, обоснование |
| Отчёт | `app/pipeline/report.py` | Кадры-доказательства: размытие лиц (YuNet), рамка вокруг объекта, JPEG в base64; JSON по схеме ТЗ |

## Почему так

- **VLM отвечает только на узкие вопросы по кропам.** На полном кадре 464×848 модель на 4 млрд параметров путается: «в комнате 0 человек», телефон вместо денег. На увеличенном фрагменте с одним вопросом точность высокая: экран ноутбука — 11 из 11 на обучающих кадрах. Поэтому CV решает, где и когда смотреть, а VLM — что там видно.
- **Время берётся из CV, смысл — из VLM.** Таймкод дают входы и выходы людей и окна сканирования (шаг 1,5 с), поэтому он привязан к конкретному кадру.
- **Нет фиксированных зон в пикселях.** Рабочее место определяется по ноутбуку, кассир — по близости к нему. Счётную машину, сейф и дверь VLM находит один раз на видео (grounding). В обучающем наборе 5 ракурсов, и все обрабатываются одним кодом. Это нужно для критерия «устойчивость»: финальное видео снято под другим углом.
- **Нормальная практика не считается нарушением.** Предварительный пересчёт руками с последующей машиной — норма (X-3). Уход кассира с заблокированным ноутбуком и чистым столом — норма (X-12, X-23, X-27). Правила проверяют именно отличие от нормы.
- **Пропуск хуже ложной тревоги, но и ложных тревог мало.** Каждый тип требует двух согласованных наблюдений: два окна подряд или два голоса VLM.

## Локальность и переносимость

- Все веса лежат локально: RT-DETR в кэше HuggingFace, Qwen3-VL в хранилище Ollama, YuNet в `models/`. При обработке видео сетевые запросы идут только к `127.0.0.1:11434` (Ollama).
- `docker-compose.yml`: два контейнера (Ollama и сервис). Веса скачиваются при сборке, далее работа офлайн (`HF_HUB_OFFLINE=1`).
- Требования: NVIDIA GPU 8 ГБ (RTX 5060 в нашем стенде), 16+ ГБ ОЗУ. Без GPU работает на CPU, но медленнее.

## Производительность (RTX 5060 8 ГБ)

Детекция занимает ~0,03 с на кадр. Вызов VLM — 0,8–1,7 с. Видео 20 с обрабатывается примерно за 30 с. Для длинных видео шаг сканирования растёт (не более ~45 окон), поэтому 145 с укладываются примерно в 100 с. Предел задачи — 270 с (`JOB_TIMEOUT_SEC`), лимит жюри — 5 минут.

## Развитие

- Дообучить детектор на классах «купюры», «счётная машина», «инкассаторская сумка», чтобы реже обращаться к VLM.
- Заменить сканирование рук на лёгкий классификатор действий (pose + clip-эмбеддинги), обученный на размеченных фрагментах банка.
- Добавить несколько камер на одну кассу и сопоставлять события между ними.
